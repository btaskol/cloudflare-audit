## 1. Resumen Ejecutivo  

El código entregado corresponde a la parte **frontend** de una herramienta interna de generación de facturas.  
Aunque el acceso está protegido por Cloudflare Access (Zero‑Trust), la propia lógica del cliente contiene varias vulnerabilidades que pueden ser explotadas por un atacante que logre inyectar datos (p. ej. mediante un producto malicioso, un mensaje de error del backend o un enlace interno).  

Los hallazgos más críticos son:

| # | Vulnerabilidad | Severidad |
|---|----------------|-----------|
| 1 | **Cross‑Site Scripting (XSS) reflejado y almacenado** a través de `innerHTML` sin sanitizar (productos, datos de la factura, `orderRef`, `customerName`). | Alta |
| 2 | **Falta de protección CSRF** en la petición `POST /generate`. | Media |
| 3 | **Inyección de datos vía `extractProductId`** – la extracción basada en una expresión regular permite manipular el ID del producto y potencialmente acceder a recursos no autorizados (IDOR). | Media |
| 4 | **Exposición de información sensible en la UI** – se muestra el precio unitario y el subtotal antes de impuestos sin ningún control de visibilidad. | Baja |
| 5 | **Ausencia de cabeceras de seguridad** (CSP, X‑Content‑Type‑Options, Referrer‑Policy, etc.). | Baja |
| 6 | **Uso de `innerHTML` para construir la tabla de resultados** → riesgo de XSS y de inyección de código arbitrario. | Baja |
| 7 | **Manejo insuficiente de errores** – los mensajes de error del backend se insertan directamente en el DOM sin escape. | Baja |
| 8 | **Dependencia de datos externos sin validación estricta** (producto, precios, descuentos). | Baja |

A continuación se detalla cada hallazgo, su impacto y las recomendaciones específicas.

## 2. Hallazgos Técnicos  

### 2.1. XSS Reflejado / Almacenado (OWASP‑A07:2021 – Cross‑Site Scripting)

| **Detalle** | El código inserta datos provenientes del servidor o del usuario directamente en el DOM mediante `innerHTML` sin ningún proceso de escape. |
|-------------|-----------------------------------------------------------------------------------|
| **Puntos de inserción** | - `runningTotal.innerHTML = lines + …` (líneas 71‑84) <br> - `resultDiv.innerHTML = …` (líneas 124‑147) <br> - `datalist` se rellena con `opt.value = `${p.name} - ${money(p.unitPriceCents)} (${p.productId})`;` (línea 101) |
| **Origen de los datos** | - `p.name` y `p.productId` provienen del endpoint `/products`. <br> - `orderRef`, `customerName` y los campos de línea provienen del usuario. <br> - `data` devuelto por `/generate` (líneas 135‑146). |
| **Impacto** | Un atacante que controle cualquiera de los valores anteriores (por ejemplo, insertando un producto con nombre `<script>alert(1)</script>`) puede ejecutar JavaScript en el navegador de cualquier empleado que abra la página, robando tokens de sesión de Cloudflare Access, cookies o realizando acciones en nombre del usuario. |
| **Recomendación** | - Utilizar **textContent** o plantillas de cadena seguras en vez de `innerHTML`. <br> - Escapar/ sanitizar cualquier dato que provenga del backend antes de insertarlo en el DOM (p. ej. mediante una librería como DOMPurify). <br> - Para el `datalist`, usar el atributo `label` o `data-*` para almacenar el ID y mostrar solo texto plano. |
| **Referencia OWASP** | <https://owasp.org/Top10/A07_2021-Identification_and_Authentication> (XSS) |

---

### 2.2. Falta de Protección CSRF (OWASP‑A08:2021 – Software and Data Integrity Failures)

| **Detalle** | La petición `POST /generate` se envía con `fetch` sin incluir ningún token anti‑CSRF ni cabecera `SameSite` explícita. |
|-------------|-----------------------------------------------------------------------------------|
| **Código afectado** | ```js
await fetch('/generate', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ orderRef, customerName, lineItems })
});
``` |
| **Impacto** | Un atacante que logre engañar a un empleado (p. ej. mediante un enlace malicioso en un correo interno) podría forzar la generación de facturas no autorizadas, modificando los datos enviados. |
| **Recomendación** | - Implementar **tokens CSRF** (por ejemplo, un valor aleatorio almacenado en una cookie `SameSite=Strict` y enviado como encabezado `X-CSRF-Token`). <br> - Configurar el endpoint `/generate` para validar dicho token. |
| **Referencia OWASP** | <https://owasp.org/Top10/A08_2021-Software_and_Data_Integrity_Failures> |

---

### 2.3. Inyección de ID de Producto – Posible IDOR (OWASP‑A04:2021 – Insecure Design)

| **Detalle** | La función `extractProductId` extrae el ID del producto mediante una expresión regular que busca el último paréntesis. Un atacante puede manipular el texto del producto (p. ej. `ProductoX (ID-123) (ID-999)`) para que el ID extraído sea el deseado. |
|-------------|-----------------------------------------------------------------------------------|
| **Código** | ```js
function extractProductId(searchValue) {
  const match = searchValue.match(/\(([^)]+)\)$/);
  return match ? match[1].trim() : null;
}
``` |
| **Impacto** | Si el backend confía únicamente en el `productId` enviado por el cliente, un usuario malintencionado podría **cambiar el ID** y facturar productos que no están en la lista o con precios diferentes (IDOR – Insecure Direct Object Reference). |
| **Recomendación** | - No confiar en el ID enviado por el cliente; validar que el nombre y el ID correspondan a un registro existente en el backend. <br> - Enviar al backend **solo el ID** (obtenido de la lista mediante un atributo `data-id` en el `<option>`), no el texto libre. |
| **Referencia OWASP** | <https://owasp.org/Top10/A04_2021-Insecure_Design> (IDOR) |

---

### 2.4. Exposición de Información Sensible en la UI (OWASP‑A02:2021 – Cryptographic Failures)

| **Detalle** | Los precios unitarios y subtotales se muestran en texto plano antes de aplicar impuestos o descuentos. En un entorno interno esto puede ser aceptable, pero si la página se comparte accidentalmente (p. ej. captura de pantalla) se revela información de precios internos. |
|-------------|-----------------------------------------------------------------------------------|
| **Impacto** | Filtración de datos de negocio que podrían ser usados por competidores o por empleados no autorizados. |
| **Recomendación** | - Evaluar si es necesario mostrar precios unitarios al usuario final. <br> - Si no es esencial, ocultar o redondear los valores. |
| **Referencia OWASP** | <https://owasp.org/Top10/A02_2021-Cryptographic_Failures> (exposición de datos) |

---

### 2.5. Ausencia de Cabeceras de Seguridad (OWASP‑A06:2021 – Vulnerable and Outdated Components)

| **Detalle** | No se observan cabeceras HTTP como **Content‑Security‑Policy**, **X‑Content‑Type‑Options**, **Referrer‑Policy**, **X‑Frame‑Options**, etc. |
|-------------|-----------------------------------------------------------------------------------|
| **Impacto** | Facilita ataques de XSS, click‑jacking y sniffing de contenido. |
| **Recomendación** | Configurar el Worker (o el origen) para enviar al menos: <br>```http
Content‑Security‑Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
X‑Content‑Type‑Options: nosniff
Referrer‑Policy: strict-origin-when-cross-origin
X‑Frame‑Options: DENY
``` |
| **Referencia OWASP** | <https://owasp.org/www-project-secure-headers/> |

---

### 2.6. Uso de `innerHTML` para Construir la Tabla de Resultados (OWASP‑A07)

| **Detalle** | En la sección de resultados (`resultDiv.innerHTML`) se concatenan valores sin escape (`orderRef`, `customerName`, `li.name`). |
|-------------|-----------------------------------------------------------------------------------|
| **Impacto** | Igual que el punto 2.1 – posibilidad de XSS reflejado. |
| **Recomendación** | - Construir el DOM mediante `createElement` y `textContent`. <br> - O bien, usar una plantilla segura (p. ej. `lit-html`) que escape automáticamente. |
| **Referencia** | Ver 2.1. |

---

### 2.7. Manejo Insuficiente de Errores (OWASP‑A09:2021 – Security Logging and Monitoring)

| **Detalle** | En caso de error del backend (`throw new Error(data.error)`) el mensaje se muestra directamente al usuario sin filtrado. |
|-------------|-----------------------------------------------------------------------------------|
| **Impacto** | Un mensaje de error que incluya trazas internas o datos sensibles puede ser expuesto a usuarios finales. |
| **Recomendación** | - Normalizar los mensajes de error que se envían al cliente (p. ej. “Error al generar la factura”). <br> - Registrar los detalles en el servidor, no en el cliente. |
| **Referencia** | <https://owasp.org/Top10/A09_2021-Security_Logging_and_Monitoring> |
